Ingress 高级配置（TLS、重写、限流）

发表于2026-05-28|更新于2026-05-28|Kubernetes进阶
|字数总计:1.9k|阅读时长:8分钟|阅读量:

前言

上一篇我们讲了 Ingress 的基础用法——域名路由、路径匹配。但实际生产环境中，光有基础路由远远不够。你需要 HTTPS 加密、需要把用户无感地从一个路径跳到另一个路径、还需要防止某个恶意调用把你的服务打挂。

这些就是 Ingress 的高级配置能力。本文用 Nginx Ingress Controller 为例，讲清楚 TLS、重写（Rewrite）、限流（Rate Limiting）三个最常用的高级特性。

一、TLS 配置——给服务加上 HTTPS

为什么需要 TLS

HTTP 是明文传输，任何中间人都能截获你的请求内容。生产环境必须有 TLS（HTTPS），否则：

  • 用户密码、Token 明文暴露
  • 浏览器标记站点为”不安全”
  • 合规过不了（等保、PCI-DSS 都要求 HTTPS）

基本流程

K8s 中 TLS 的配置分两步：

  1. 把证书和私钥存进 Secret
  2. Ingress 资源引用这个 Secret

自动续期：cert-manager

手动更新证书太麻烦，生产环境一般用 cert-manager 自动申请和续期 Let’s Encrypt 证书。

核心思路：

  1. 安装 cert-manager
  2. 创建 ClusterIssuer（定义证书颁发机构）
  3. Ingress 加注解自动触发证书申请

cert-manager 检测到这个 Ingress 后，会自动：

  • 向 Let’s Encrypt 发起 ACME 挑战
  • 验证域名所有权
  • 获取证书并存入 blog-tls-auto Secret
  • 证书快过期时自动续期

二、重写（Rewrite）——无感路径跳转

什么是重写

重写是指：用户访问的路径 和 后端服务实际收到的路径 不一样，Ingress 在转发时帮你做路径转换。

典型场景：

用户访问路径 后端服务实际路径 说明
/api/users /users 去掉前缀
/v1/orders /api/orders 路径映射
/old-path /new-path 旧路径迁移

注解方式配置重写

Nginx Ingress 通过注解控制重写行为：

关键点解释：

  • path: /api(/|$)(.*) —— 正则捕获组，(.*) 捕获 /api/ 后面的所有内容
  • rewrite-target: /$2 —— $2 对应第二个捕获组，即 (.*) 匹配的内容
  • 用户访问 /api/users/list → 后端收到 /users/list

三、限流（Rate Limiting）——保护后端不被打挂

为什么需要限流

没有限流，以下场景会直接搞垮你的服务：

  • 某个爬虫疯狂请求你的 API
  • 客户端 bug 导致死循环调用
  • DDoS 攻击
  • 突发流量超过后端处理能力

限流的核心思想：超过阈值的请求直接拒绝，保护后端稳定性。

Nginx Ingress 限流原理

Nginx 的限流基于漏桶算法（Leaky Bucket），本质是：

  • 请求进来，先检查是否超过速率限制
  • 超过则返回 503（默认）
  • 未超过则放行

基础限流配置

常用限流注解

注解 说明 示例
limit-rps 每秒请求数 "10" = 10 req/s
limit-rpm 每分钟请求数 "100" = 100 req/min
limit-burst-multiplier 突发倍数 "2" = 允许 2 倍突发
limit-whitelist 白名单 CIDR "10.0.0.0/8,192.168.0.0/16"
limit-connections 并发连接数限制 "50"

按客户端 IP 限流

生产环境通常希望每个用户独立限流，而不是全局共享一个限额。

总结

能力 核心注解 / 配置 典型场景
TLS tls 字段 + cert-manager HTTPS 加密
重写 rewrite-target + 正则 path 路径映射、前缀去除
限流 limit-rps / limit-rpm 防爬虫、防 DDoS
白名单 whitelist-source-range 内网跳过限流

这三个能力是生产环境 Ingress 配置的标配。TLS 保证安全，重写保证路径灵活，限流保证稳定。掌握这三个，你的 Ingress 配置就能应对大部分生产场景了。
