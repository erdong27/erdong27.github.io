StorageClass 动态存储供应

在 Kubernetes 中管理存储时，你可能会遇到这样的场景：

  • 每次创建 PVC 都要手动创建 PV，太麻烦
  • 不同应用需要不同性能的存储（SSD、HDD）
  • 在云平台上，希望存储能随 Pod 自动创建和删除

这时候，StorageClass 就派上用场了。

什么是 StorageClass？

StorageClass（存储类） 是 Kubernetes 中用于定义存储配置文件的资源对象。它允许你：

  1. 动态创建 PV：当 PVC 请求存储时，自动创建对应的 PV
  2. 定义存储参数：比如存储类型、IOPS、回收策略等
  3. 对接不同存储后端：AWS EBS、GCE PD、Ceph RBD、NFS 等

通俗地说，StorageClass 就像是一个存储菜单，你可以根据需求选择不同规格的存储，而无需手动准备每一份。

为什么需要 StorageClass？

传统方式的痛点

在没有 StorageClass 之前，使用存储的流程是这样的：

这种方式有三个问题：

  1. 运维负担重：每个 PV 都要手动创建，100 个应用就要创建 100 个 PV
  2. 资源浪费：PV 是集群资源，提前创建多了浪费，少了不够用
  3. 无法按需定制：不同应用对存储性能要求不同，难以灵活配置

StorageClass 的优势

有了 StorageClass，流程变成：

优势：

  • 自动化：无需手动创建 PV
  • 按需供应：用到才创建，不浪费
  • 参数化配置：通过 StorageClass 定义存储参数

StorageClass 的核心概念

一个 StorageClass 包含以下关键字段：

1. provisioner（存储插件）

这是最重要的字段，指定由哪个存储插件来创建 PV。

常见的 provisioner：

  • kubernetes.io/aws-ebs（AWS）
  • kubernetes.io/gce-pd（GCP）
  • kubernetes.io/azure-disk（Azure）
  • rox.default.svc.cluster.local（Rook Ceph）
  • nfs-client（NFS）

2. parameters（参数）

传递给 provisioner 的参数，不同 provisioner 支持的参数不同。

例如 AWS EBS：

3. reclaimPolicy（回收策略）

定义当 PVC 被删除时，PV 和底层存储如何处理：

  • Delete：删除 PVC 时，自动删除 PV 和底层存储（常用）
  • Retain：删除 PVC 时，保留 PV 和底层存储，需手动清理

4. allowVolumeExpansion（允许扩容）

是否允许扩容 PVC：

如果设置为 true，可以通过编辑 PVC 的 resources.requests.storage 字段来扩容。

5. volumeBindingMode（绑定模式）

控制 PV 的创建和绑定时机：

  • Immediate：创建 PVC 时立即创建 PV（默认）
  • WaitForFirstConsumer：延迟到 Pod 调度时再创建 PV（推荐用于本地存储）

WaitForFirstConsumer 的好处是：可以确保 PV 和 Pod 在同一个可用区。

常见问题与排查

1. PVC 一直 Pending

原因：

  • StorageClass 不存在
  • Provisioner 配置错误
  • 存储后端不可用（比如 AWS API 限流）

排查：

2. PV 创建成功但无法挂载

原因：

  • 节点无法访问存储后端（网络问题）
  • 权限不足（AWS IAM、Ceph 认证等）

排查：

3. 删除 PVC 后存储未清理

原因：

  • reclaimPolicy 设置为 Retain

解决：
手动删除 PV 和底层存储。

最佳实践

  1. 使用 WaitForFirstConsumer：对于云平台存储，避免 PV 和 Pod 不在同一个可用区
  2. 设置 allowVolumeExpansion: true：方便后续扩容
  3. 根据业务选择存储类型：数据库用 SSD，日志用 HDD，冷数据用归档存储
  4. 定期清理无用的 PV/PVC：避免占用资源和成本
  5. 监控存储使用率：防止存储空间不足

总结

StorageClass 是 Kubernetes 动态存储供应的核心组件，它通过抽象存储后端和参数化配置，让存储管理变得简单高效。

核心要点：

  • StorageClass 定义了存储的”配方”
  • PVC 通过 storageClassName 指定使用哪个 StorageClass
  • Provisioner 根据 StorageClass 的配置自动创建 PV
  • 不同场景选择不同的 StorageClass（性能、成本、可用性）

掌握 StorageClass，你的 K8s 存储管理就上了一个新台阶！
